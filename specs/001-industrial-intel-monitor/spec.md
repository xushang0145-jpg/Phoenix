## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动生成竞品情报周报 (Priority: P1)

作为情报分析员，我希望系统按周期自动采集工业自动化竞品的公开动态，完成清洗与整理，并生成一份可阅读的竞品情报周报，从而替代人工逐站浏览。

**Why this priority**: 这是作品的核心价值闭环（采集→治理→报告），单独实现即可交付一个可用 MVP。

**Independent Test**: 配置 4 家竞品后运行一次全流程，能产出包含覆盖统计、竞品动态与图表的 HTML 报告，即视为通过。

**Acceptance Scenarios**:

1. **Given** 已配置 4 家竞品与 3 类数据源，**When** 触发一次全流程运行，**Then** 系统在近 12 个月范围内入库不少于 600 条去重情报，并生成一份 HTML 报告。
2. **Given** 报告中存在图表，**When** 用户查看任一图表，**Then** 图表下方至少有 1 句结论，并附原始来源链接。

---

### User Story 2 - 对情报做 AI 加工与主题洞察 (Priority: P2)

作为战略/研发人员，我希望系统对非结构化情报自动摘要、抽取关键实体并聚类成主题，从而快速看清竞品在哪些产品线与技术主题上发力。

**Why this priority**: 在可用闭环之上体现 NLP 与洞察深度，是区分“报表”与“情报”的关键，但依赖 US1 的数据。

**Independent Test**: 对已入库情报运行 AI 加工，抽查 30 条摘要可读、实体合理，且能输出主题列表与主题随时间的趋势图。

**Acceptance Scenarios**:

1. **Given** 已入库的原始情报，**When** 运行 AI 加工，**Then** 每条情报具备摘要与主题归属，并生成主题趋势图。
2. **Given** 二次运行同一批数据，**When** 触发 AI 加工，**Then** 命中缓存、不重复产生调用成本。

---

### User Story 3 - 用自然语言查询竞品动态 (Priority: P3 · v0.0.0 不实现，移至 v0.1+)

作为研发或产品经理，我希望用自然语言提问（如“魏德米勒最近在储能连接器上有什么动作？”），系统基于情报证据作答并标注来源。

**Why this priority**: 差异化亮点，直接对应岗位的 RAG 要求；可独立于报告实现，但需已有情报数据支撑。

**Independent Test**: 用 10 个预设问题测试，至少 7 个回答正确且给出可追溯来源。

**Acceptance Scenarios**:

1. **Given** 已构建向量索引，**When** 用户提出与情报相关的问题，**Then** 系统返回基于检索证据的答案并标注来源。
2. **Given** 检索不到可靠证据，**When** 用户提问，**Then** 系统明确提示“无可靠依据”，不得编造。

---

### Edge Cases

- 目标站点改版或新增反爬时，采集如何降级并记录失败？
- 页面内容由 JavaScript 动态渲染时，如何保证正文完整？
- 同一稿件被多站转载时，如何识别为近似重复？
- 条目缺少发布日期或日期格式不统一时，如何处理？
- 中英文混合情报时，摘要与聚类如何保持一致效果？
- LLM 服务不可用或超出预算时，流水线如何降级？
- 问答检索结果为空或置信度低时，如何避免幻觉？

## Requirements *(mandatory)*

### Functional Requirements

**采集**

- **FR-001**: System MUST 通过配置文件定义竞品、数据源与产品线，无需改代码。
- **FR-002**: System MUST 在调度触发后采集所有已启用数据源的新增内容。
- **FR-003**: System MUST 支持官网新闻列表、RSS、行业媒体列表页三类数据源。
- **FR-004**: System MUST 对 JavaScript 动态渲染页面使用无头浏览器获取完整内容。
- **FR-005**: System MUST 对请求限速、失败重试，并缓存原始页面。
- **FR-006**: System MUST 为每条情报记录来源、URL、抓取时间与状态。

**清洗与治理**

- **FR-007**: System MUST 抽取正文并剔除导航、广告等噪声。
- **FR-008**: System MUST 对完全重复与近似重复的情报去重。
- **FR-009**: System MUST 解析多种日期格式并识别文本语言。
- **FR-010**: System MUST 为每条情报打标竞品与产品线。
- **FR-011**: System MUST 将清洗结果写入统一 schema 的存储。

**AI 加工**

- **FR-012**: System MUST 为每条情报生成不超过 120 字的摘要（已确认 Q5）。
- **FR-013**: System MUST 抽取公司、产品、技术、地区四类实体。
- **FR-014**: System MUST 基于 embedding 将情报聚类为可命名的主题。
- **FR-015**: System MUST 缓存 AI 结果以避免重复计算与重复计费。
- **FR-016**: System SHOULD 在启用时输出情报的情感倾向。

**量化分析**

- **FR-017**: System MUST 输出按月的发布频率时序。
- **FR-018**: System MUST 输出产品线热度分布。
- **FR-019**: System MUST 输出技术主题随时间的趋势。
- **FR-020**: System MUST 输出「竞品 × 产品线」动作对比矩阵。
- **FR-021**: System MUST 将图表保存为可复用的文件。

**报告**

- **FR-022**: System MUST 生成含固定章节的 HTML 情报报告。
- **FR-023**: System MUST 在每张图表下给出至少一句结论。
- **FR-024**: System MUST 在报告中给出至少 3 条对我方启示。
- **FR-025**: System MUST 在报告附录附上原始来源链接。
- **FR-026**: System SHOULD 支持导出 PDF（报告主形态已确认为静态 HTML，Q1；PDF 为可选增强）。

**情报问答**（v0.0.0 不实现，整体移至 v0.1+；保留占位以保持需求编号稳定）

- **FR-027**: System MUST 将情报构建为可检索的向量索引。【v0.1+】
- **FR-028**: System MUST 在回答用户问题时标注依据来源。【v0.1+】
- **FR-029**: System MUST 在证据不足或置信度低时明确提示“无可靠依据”。【v0.1+】
- **FR-030**: System MUST 支持按竞品、产品线、时间范围过滤检索范围。【v0.1+】

**运维**

- **FR-031**: System MUST 提供一键运行入口跑通全流程。
- **FR-032**: System SHOULD 支持按日或按周调度。
- **FR-033**: System MUST 记录运行日志与统计（条数、耗时、失败数）。

### Key Entities *(include if feature involves data)*

- **情报条目（Intel Item）**：一条公开情报，含标题、正文、摘要、来源、发布日期、语言、所属竞品、产品线、主题、实体、原文链接。
- **竞品（Competitor）**：被监测的目标企业，含名称、别名、官网、关注产品线。
- **数据源（Source）**：采集目标，含类型（官网/RSS/媒体）、URL、解析规则、采集频率。
- **主题（Topic）**：由聚类得到的技术/业务主题，含名称、关键词、关联情报数量。
- **报告（Report）**：某一周期内生成的情报报告，含周期、覆盖统计、图表、结论与我方启示。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 配置 4 家竞品并运行全流程后，近 12 个月去重情报不少于 600 条，且每家竞品不少于 50 条。
- **SC-002**: 在新环境按 README 执行，一条命令即可跑通全流程并产出报告。
- **SC-003**: 随机抽检 30 条，正文抽取准确率不低于 85%，发布日期有效率不低于 95%，重复率低于 2%。
- **SC-004**: 报告包含不少于 4 张图表，每张图附结论，且包含不少于 3 条对我方启示。
- **SC-005**（v0.1+，不在 v0.0.0 验收范围）: 用 10 个预设问题测试问答，至少 7 个回答正确且附可追溯来源。
- **SC-006**: 评审者能在 5 分钟内从报告或演示中理解「目标—方法—发现」。

## Assumptions

- 目标数据源公开可访问，允许低频、克制的抓取，且不涉及个人隐私数据。
- 采用按日或按周的批量更新，不要求实时/流式处理。
- 运行环境为 Python 3.10+ 的单机环境。
- 具备可用的 LLM 能力（云端 API 或本地小模型），预算与算力有限，因此需缓存与批量控制成本。
- 情报以中文为主，英文官网作为加分数据源。
- 本项目为求职作品，追求可复现、可解释、可演示，而非生产级高可用。
